# Docs Dev Landing

## Описание проекта

**Docs Dev Landing** — проект по созданию адаптивного лендинга на основе предоставленного дизайна или референса.

Разработка выполняется поэтапно: от базовой структуры проекта и настройки стилей до реализации всех секций страницы, анимаций и адаптации под различные устройства.

## 1. Структура проекта

Создаём главную папку проекта и организуем файлы следующим образом:

```text
docs-dev-landing/
├── index.html
├── css/
│   └── style.css
├── js/
│   └── main.js
└── assets/
    ├── images/
    ├── icons/
    └── fonts/
```

### Назначение файлов и папок

- **`index.html`** — основной HTML-документ, содержащий структуру страницы и подключения необходимых библиотек.
- **`css/style.css`** — пользовательские стили проекта, CSS-переменные, цвета, типографика и дополнительные правила оформления.
- **`js/main.js`** — JavaScript-логика, анимации GSAP, обработчики событий и интерактивные элементы.
- **`assets/images/`** — изображения и графические материалы.
- **`assets/icons/`** — иконки и SVG-файлы.
- **`assets/fonts/`** — локальные шрифты, если они необходимы.

## 2. Используемые библиотеки

В проекте используем две основные библиотеки.

### Tailwind CSS

Версия: `^3.4.19`

Tailwind CSS используется для быстрой разработки интерфейса с помощью utility-классов непосредственно в HTML.

Основные задачи:

- построение сеток и расположение элементов;
- управление отступами и размерами;
- настройка типографики;
- оформление кнопок, карточек и других компонентов;
- реализация адаптивных стилей;
- управление отображением элементов на разных разрешениях.

Подключение через CDN в `index.html`:

```html
<script src="https://cdn.tailwindcss.com"></script>
```

### GSAP

Версия: `^3.14.2`

GSAP используется для создания анимаций и динамических эффектов.

Основные задачи:

- анимация появления секций и элементов;
- плавное появление заголовков, изображений и карточек;
- анимация при прокрутке страницы;
- управление последовательностями анимаций;
- создание интерактивных эффектов;
- настройка временных задержек, длительности и плавности переходов.

Подключение через CDN в `index.html`:

```html
<script src="https://cdn.jsdelivr.net/npm/gsap@3.14.2/dist/gsap.min.js"></script>
```

Если понадобится анимация при прокрутке, дополнительно подключаем ScrollTrigger:

```html
<script src="https://cdn.jsdelivr.net/npm/gsap@3.14.2/dist/ScrollTrigger.min.js"></script>
```

Регистрация плагина выполняется в `js/main.js`:

```javascript
gsap.registerPlugin(ScrollTrigger);
```

**Важно:** CDN-версия Tailwind CSS 3 предназначена прежде всего для разработки и прототипирования. Для production-сборки рекомендуется настроить Tailwind через CLI или сборщик, чтобы удалить неиспользуемые стили. Версии библиотек при использовании CDN фиксируем явно, чтобы обеспечить предсказуемое поведение проекта.

## 3. Организация CSS и цветовых переменных

Все пользовательские стили храним в файле `css/style.css`.

В начале файла создаём отдельный блок CSS-переменных, в котором централизованно определяем цвета и другие общие значения проекта.

Пример:

```css
:root {
  /* Основные цвета */
  --color-primary: #2563eb;
  --color-secondary: #7c3aed;

  /* Цвета фона */
  --color-background: #ffffff;
  --color-background-alt: #f8fafc;

  /* Цвета текста */
  --color-text: #0f172a;
  --color-text-muted: #64748b;

  /* Дополнительные цвета */
  --color-border: #e2e8f0;
  --color-accent: #38bdf8;

  /* Общие параметры */
  --container-width: 1200px;
  --section-spacing: 96px;
  --border-radius: 16px;
}
```

Приведённые значения являются стартовым примером. При реализации проекта заменяем их на цвета и параметры, соответствующие исходному дизайну.

Используем переменные во всех пользовательских стилях:

```css
body {
  color: var(--color-text);
  background-color: var(--color-background);
}

.section {
  padding-block: var(--section-spacing);
}

.card {
  border: 1px solid var(--color-border);
  border-radius: var(--border-radius);
}
```

Это позволяет централизованно изменять визуальную систему проекта, сохранять единообразие оформления и упрощать дальнейшую поддержку.

## 4. Подключение файлов в HTML

В `index.html` подключаем Tailwind CSS, пользовательские стили, GSAP и основной JavaScript-файл.

Пример базовой структуры документа:

```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">

  <meta
    name="description"
    content="Docs Dev Landing — адаптивный лендинг."
  >

  <title>Docs Dev Landing</title>

  <!-- Tailwind CSS -->
  <script src="https://cdn.tailwindcss.com"></script>

  <!-- Пользовательские стили -->
  <link rel="stylesheet" href="css/style.css">
</head>
<body>

  <header class="site-header">
    <!-- Секция шапки -->
  </header>

  <main>
    <!-- Секции лендинга -->
  </main>

  <footer class="site-footer">
    <!-- Секция подвала -->
  </footer>

  <!-- GSAP -->
  <script src="https://cdn.jsdelivr.net/npm/gsap@3.14.2/dist/gsap.min.js"></script>

  <!-- GSAP ScrollTrigger -->
  <script src="https://cdn.jsdelivr.net/npm/gsap@3.14.2/dist/ScrollTrigger.min.js"></script>

  <!-- Пользовательский JavaScript -->
  <script src="js/main.js"></script>
</body>
</html>
```

Скрипты подключаем в конце `body`, чтобы HTML-разметка уже была доступна к моменту выполнения пользовательского JavaScript.

## 5. Поэтапная разработка лендинга

Работу над проектом выполняем последовательно, секция за секцией.

### Этап 1. Анализ дизайна

- Изучаем предоставленный макет или референс.
- Определяем структуру страницы и порядок секций.
- Выявляем повторяющиеся компоненты.
- Определяем шрифты, цвета, размеры, отступы и пропорции.
- Отмечаем элементы, которым потребуются анимации.
- Определяем поведение интерфейса на мобильных устройствах.

### Этап 2. Создание базовой структуры

- Создаём папки и файлы проекта.
- Подключаем Tailwind CSS и GSAP.
- Настраиваем CSS-переменные.
- Определяем базовые стили документа.
- Создаём общие контейнеры и вспомогательные классы.
- Проверяем корректность подключений.

### Этап 3. Вёрстка секций

Реализуем лендинг последовательно, начиная с первой секции и переходя к следующей только после проверки текущей.

Рекомендуемый порядок:

1. Header — шапка сайта и навигация.
2. Hero — первый экран, основной заголовок, описание и CTA-кнопки.
3. Основные информационные секции.
4. Карточки, преимущества и блоки с изображениями.
5. Дополнительные интерактивные секции.
6. CTA — завершающий призыв к действию.
7. Footer — подвал сайта.

Фактический состав секций определяем по исходному дизайну.

Каждую секцию сначала реализуем структурно, затем настраиваем её визуальное оформление, адаптивность и необходимые интерактивные эффекты.

### Этап 4. Анимации GSAP

После создания основной разметки добавляем анимации.

Пример простой анимации первого экрана:

```javascript
gsap.from(".hero-title", {
  y: 40,
  opacity: 0,
  duration: 0.8,
  ease: "power3.out"
});
```

Пример появления элементов при прокрутке:

```javascript
gsap.from(".section-content", {
  y: 30,
  opacity: 0,
  duration: 0.7,
  ease: "power2.out",
  scrollTrigger: {
    trigger: ".section-content",
    start: "top 85%",
    once: true
  }
});
```

Анимации должны дополнять дизайн, не мешать взаимодействию с сайтом и не создавать лишних задержек при загрузке контента.

Также учитываем настройку `prefers-reduced-motion`, чтобы пользователи, предпочитающие уменьшенное движение, могли комфортно пользоваться сайтом.

### Этап 5. Адаптивная вёрстка

Весь проект разрабатываем с учётом различных размеров экранов.

Обязательные контрольные разрешения:

- **320–375 px** — небольшие мобильные устройства;
- **376–767 px** — мобильные устройства;
- **768–1023 px** — планшеты;
- **1024–1279 px** — небольшие ноутбуки;
- **1280 px и выше** — большие экраны и настольные компьютеры.

При адаптации проверяем:

- отсутствие горизонтальной прокрутки;
- корректное изменение сеток и колонок;
- размеры заголовков и основного текста;
- отступы между секциями;
- масштабирование изображений;
- работу навигации и мобильного меню;
- удобство кнопок и интерактивных элементов;
- корректное поведение анимаций;
- сохранение визуальной иерархии дизайна.

Используем подход mobile-first там, где это удобно, и адаптивные классы Tailwind CSS для управления расположением и размерами элементов.

Дополнительные правила для отдельных разрешений размещаем в `css/style.css`.

### Этап 6. Проверка и оптимизация

После завершения всех секций:

- проверяем страницу в актуальных браузерах;
- тестируем мобильную, планшетную и десктопную версии;
- проверяем все ссылки, кнопки и интерактивные элементы;
- устраняем ошибки в консоли;
- проверяем загрузку изображений, шрифтов и библиотек;
- оптимизируем анимации и тяжёлые визуальные элементы;
- проверяем доступность интерфейса с клавиатуры;
- убеждаемся, что контент не перекрывается и не выходит за границы экрана.

## 6. Правила разработки

1. Делаем вёрстку максимально близко к исходному дизайну.
2. Разрабатываем секции последовательно, без хаотичного перехода между частями страницы.
3. Используем Tailwind CSS для основной компоновки и типовых стилистических правил.
4. Используем `css/style.css` для CSS-переменных, общих компонентов и специфических стилей.
5. Используем `js/main.js` для анимаций, интерактивности и дополнительной логики.
6. Не дублируем стили и JavaScript без необходимости.
7. Повторяющиеся значения оформляем через переменные и общие классы.
8. Не добавляем анимации, которые противоречат исходному дизайну.
9. Проверяем адаптивность каждой секции сразу после её реализации.
10. Поддерживаем понятную и последовательную структуру кода.

## 7. Критерии готовности проекта

Проект считается завершённым, когда:

- все секции лендинга свёрстаны;
- визуальное оформление соответствует референсу;
- Tailwind CSS и GSAP подключены и работают корректно;
- цветовые переменные вынесены в `css/style.css`;
- интерактивные элементы работают;
- анимации реализованы там, где они необходимы;
- страница адаптирована под мобильные устройства, планшеты и компьютеры;
- отсутствуют критические ошибки в консоли;
- разметка и стили организованы в соответствии со структурой проекта.
